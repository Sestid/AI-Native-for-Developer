# Subagents · 委派层

> Layer 4 · 委派层。把复杂任务拆给专职子智能体，各司其职、并行协作，
> 避免「一个 Agent 啥都干」导致的上下文污染与质量下滑。

---

## 为什么要委派

- **保护主上下文**：把大量检索 / 探索丢给子智能体，主线程只收结论，不被噪音淹没。
- **专职专精**：每个子智能体带固定职责与产出格式，输出更稳定。
- **可并行**：相互独立的子任务同时跑，缩短总时长。

---

## 何时委派 / 何时不委派

| 委派 | 不委派 |
|------|--------|
| 跨多文件的探索 / 调研（> 3 次检索） | 读一个已知文件 |
| 独立可并行的子任务 | 有强依赖、必须串行的步骤 |
| 需要大量中间结果、但主线程只要结论 | 一两步就能完成的小事 |

> 委派有成本：别为了用而用。简单任务直接做更快。

---

## 角色清单

| 角色 | 职责 | 产出 | 何时召唤 |
|------|------|------|----------|
| [architect](architect.md) | 读需求 + 探代码，出实现方案 | Plan（文件清单 / 分层 / 步骤） | 动手前的方案设计 |
| [coder](coder.md) | 按 Plan 实现，边写边交修改清单 | 代码 diff + 修改记录 | 方案确认后执行 |
| [reviewer](reviewer.md) | 对照规范挑刺，找 bug 与越界 | 问题清单（按严重度） | 实现完成后验收 |

---

## 协作主线

```
需求 → [architect] 出 Plan → 人确认边界
     → [coder] 按 Plan 实现 → 交修改清单
     → [reviewer] 对照规范审查 → 出问题清单
     → 人验收 / 迭代
```

每个角色都以 `memory/project.md` + `memory/conventions.md` 为最高准则。

---

## 如何调用

在主对话里用 Agent / Task 能力指定子智能体类型，把对应角色文件的「职责 + 产出格式」作为
该子智能体的工作约束。每个角色文件即为该子智能体的「岗位说明书」。
