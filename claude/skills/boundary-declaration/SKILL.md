# 边界声明门禁

> 一句话定位：开工前圈地。圈得越清晰，AI 越不容易越界，review 越快。

---

## 触发时机（When to use）

- 任何「即将动手改代码」的任务，写代码前必过此门禁。
- L1 隔离新增可简化声明，L2 / L3 必须完整声明。

---

## 输入（Input）

- 一句话需求。
- 已抽好的开发文档（见 `prd-to-plan`）。
- 改动级别判断（L1 / L2 / L3，定义见 `memory/project.md`）。

---

## 流程（Steps）

1. 判定改动级别（L1 / L2 / L3）。
2. 列「即将创建的文件路径」。
3. 列「即将修改的文件路径 + 每个文件的改动要点（一行一句）」。
4. 明确「不会触碰的相邻代码」，并说明「不改 X，因为 Y」。
5. 列风险点：可能破坏的现有功能。
6. **等人确认「OK，开始」后**才动手。
7. 写完后把「实际触碰文件清单」再贴一次，与事前声明对账。

---

## 产出（Output）

- 一份边界声明（创建清单 / 修改清单 / 不触碰说明 / 风险点）。
- 完成后一份对账表（声明 vs 实际，差异需解释）。

---

## 可直接粘贴的 Prompt

```text
任务：<一句话需求>
改动级别：L1 / L2 / L3（三选一）

请在动手前先输出：
1. 即将创建的文件路径列表
2. 即将修改的文件路径列表 + 每个文件的改动要点（一行一句）
3. 不会触碰的相邻代码（明确说"不改 X，因为 Y"）
4. 风险点：可能会破坏的现有功能

我确认无误后再说"OK，开始"，你才可以写代码。
不要先写代码再补声明。
```

---

## 卡点信号（Stop signals）

- 触碰文件 > 10 个 → 拆 PR。
- L2 任务发现需要改公共抽象 → 升级为 L3，先出 Plan。
- 实际触碰文件超出声明 → 立刻停下，解释或回滚。

---

## 自检清单（Self-check）

- [ ] 改动级别已声明
- [ ] 创建 / 修改清单完整
- [ ] 已说明不触碰哪些相邻代码及原因
- [ ] 已列风险点
- [ ] 完成后做了声明 vs 实际的对账
