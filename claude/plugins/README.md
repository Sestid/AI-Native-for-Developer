# Plugins · 分发层

> Layer 5 · 分发层。把扩展能力（MCP 工具、自定义命令、插件）做版本管理与团队分发，
> 解决「团队工具不一致、各装各的」问题。

---

## 这一层管什么

- **MCP 服务器配置**：团队统一用哪些 MCP（设计稿、文档、数据库…），配置版本化。
- **自定义 slash 命令 / skill 包**：可被打包分发给团队成员的能力。
- **第三方插件的版本锁定**：保证所有人用同一版本，避免「我这能跑你那不行」。

---

## 推荐 MCP 工具（按项目实际启用）

| 名称 | 干什么 | 关键场景 |
|------|--------|----------|
| Figma | 读设计稿、生成代码、code-connect | 还原视觉、对接 design tokens |
| Context7 | 拉第三方库最新文档 | 防止 AI 幻觉 API、查新语法 |
| `<自定义>` | `<...>` | `<...>` |

> 用 MCP 的原则：
> - ✅ 让 AI 联网：第三方库新版本、设计稿规格、不确定的 API 行为。
> - ❌ 禁止 AI 联网：业务规则、内部接口约定、PRD 解读——这些只能来自人给的上下文。

---

## 目录约定

```
plugins/
├── README.md          # 本文件
├── mcp/               # MCP 服务器配置（可提交，敏感信息走环境变量）
└── commands/          # 自定义命令 / 可分发 skill 包
```

> 真正的 MCP 启用配置写在仓库根的 `settings.json`（或 `.mcp.json`）。
> 本目录用于沉淀「团队约定的工具清单与版本」，作为分发依据。

---

## 分发原则

1. **版本锁定**：插件 / MCP 记录确切版本，团队统一。
2. **配置即代码**：能提交的配置进仓库，敏感凭证走环境变量，绝不硬编码。
3. **最小集合**：只引入真正用得上的工具，避免工具膨胀。
4. **文档先行**：每引入一个工具，在上表登记「干什么 + 关键场景」。
